# 评分点映射

## 1. 需求分析 20%

对应产物：

- `docs/requirements.md`
- 用例图、状态图、需求优先级表。

覆盖策略：

- 明确用户、管理员、访客、家庭设备、报警服务等利益相关方。
- 拆分功能需求、非功能需求、约束需求。
- 每个核心需求给出可验证的验收标准。
- 避免只写概念，确保能映射到后续原型功能。

## 2. 软件设计 20%

对应产物：

- `docs/design.md`
- 架构图、ER 图、顺序图、活动图、接口设计表、界面设计说明。

覆盖策略：

- 采用表现层、业务逻辑层、数据访问层、数据存储层的分层设计。
- 模块划分为认证、设备、监控、告警、录像、语音指令、场景联动、日志。
- SQLite 表设计覆盖用户、房间、设备、告警、录像、场景规则、操作日志。
- 接口与页面设计和代码保持一致。

## 3. 系统测试 15%

对应产物：

- `docs/test-plan-and-cases.md`
- `tests/`

覆盖策略：

- 功能测试覆盖登录、设备控制、异常报警、录像筛选、语音指令解析。
- 安全测试覆盖未登录访问、越权操作、错误密码、非法参数。
- 兼容性测试记录 Windows + Chrome / Edge。
- 性能测试以本地接口响应时间和页面加载为主，不虚构真实高并发结果。

## 4. 项目管理 15%

对应产物：

- `docs/project-management.md`
- 甘特图、任务分工表、风险清单、进度记录。

覆盖策略：

- 按 2 个月项目周期模拟需求、设计、开发、测试、演示准备。
- 结合小组实际人员填写角色分工。
- 记录版本管理规范、Issue 任务、风险识别与应对策略。
- 保留阶段审阅记录，体现过程管理。

## 5. 程序代码 20%

对应产物：

- `src/`
- `data/`
- `tests/`

覆盖策略：

- 至少实现 7 个核心用例，超过“实现用例不少于 3 个”的规模线。
- 源文件数量大于 5 个。
- 关键代码行数大于 500 行。
- 保持模块化和可维护性，避免把所有逻辑堆在一个文件里。
- 提供启动脚本、种子数据和测试代码。

## 6. 提交成果完整性 10%

对应产物：

- 文档、代码、测试数据、截图、运行说明、演示材料。

覆盖策略：

- 所有文档统一放在 `docs/`。
- 所有图表原始素材放在 `diagrams/`。
- 最终可提交材料汇总到 `deliverables/`。
- 提供清晰的部署与操作说明，保证老师可以运行或按截图/视频理解系统。
