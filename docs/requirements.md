# 需求分析文档

## 1. 文档目的

本文档面向“全屋智能安防与语音控制系统”项目，定义系统的业务背景、利益相关方、功能需求、非功能需求、约束需求、核心用例和验收标准。本文档对应课程考核要求中的“2.1 需求分析”和评分标准中的“需求分析 20%”。

## 2. 项目背景

全屋智能系统通过物联网、人工智能和数据分析技术，将家庭中的摄像头、门窗传感器、烟雾传感器、灯光、空调、门锁和警报器等设备进行统一管理，实现家庭安全、环境舒适和远程控制。本项目选择全屋智能方向下的“家居视频监控与安防智能系统”为主线，并加入语音交互助手能力，形成一个可演示、可测试、可维护的本地 Web 原型。

## 3. 利益相关方

| 编号 | 利益相关方 | 诉求 |
|---|---|---|
| S1 | 家庭成员 | 查看家庭安全状态，控制设备，接收并处理告警。 |
| S2 | 管理员 | 管理用户、设备、场景规则和审计日志。 |
| S3 | 访客查看者 | 在授权范围内查看监控状态和录像信息。 |
| S4 | 智能设备/传感器 | 上报状态、异常事件和环境数据。 |
| S5 | 课程考核组 | 检查软件工程制品完整性、原型功能、测试结果和代码质量。 |

## 4. 业务边界

### 4.1 范围内

- 支持用户登录、角色权限和操作审计。
- 支持多房间、多设备状态管理。
- 支持实时监控看板，以模拟视频流展示摄像头画面。
- 支持入侵、烟雾、跌倒、门窗异常、移动检测等异常事件模拟。
- 支持异常告警、录像记录、声光警报器和灯光联动。
- 支持按关键词检索录像和事件记录。
- 支持文本形式的语音指令模拟，用于控制设备、查询摄像头、触发告警和切换场景。
- 支持可选 DeepSeek 大模型语音指令解析，并在未配置或解析失败时回退到本地规则。
- 支持离家安防、回家模式、夜间巡航、紧急警戒等场景模式。

### 4.2 范围外

- 不接入真实摄像头、真实云台、真实短信电话或真实智能家居硬件。
- 不训练真实计算机视觉模型，智能异常检测采用规则和模拟事件实现。
- 不部署到公网，仅要求本地可运行和课堂可演示。

## 5. 功能需求

| 编号 | 需求名称 | 需求描述 | 优先级 | 验收标准 |
|---|---|---|---|---|
| FR-01 | 用户登录 | 系统应支持管理员、家庭成员、访客三类用户登录。 | 高 | 正确账号可登录，错误密码被拒绝。 |
| FR-02 | 角色权限 | 系统应根据角色限制设备控制、告警处理和日志查看。 | 高 | 访客不能控制设备，管理员能查看审计日志。 |
| FR-03 | 设备状态管理 | 系统应展示摄像头、传感器、灯光、空调、门锁、警报器的状态。 | 高 | 看板显示设备名称、房间、类型、在线状态和电量。 |
| FR-04 | 设备控制 | 家庭成员和管理员可以调整灯光、空调、摄像头、门锁、警报器等状态。 | 高 | 点击控制按钮后数据库和界面状态同步变化。 |
| FR-05 | 实时监控 | 系统应展示多房间摄像头模拟画面和摄像头状态。 | 高 | 首页至少展示门口、客厅、卧室摄像头画面。 |
| FR-06 | 异常告警 | 系统应支持模拟入侵、烟雾、跌倒、门窗异常、移动检测事件。 | 高 | 触发事件后生成未处理告警。 |
| FR-07 | 联动响应 | 高危事件应自动触发声光警报器、灯光或摄像头联动。 | 高 | 入侵事件触发后警报器为 active，摄像头为 active。 |
| FR-08 | 告警处置 | 用户应能确认并关闭告警，系统记录处置说明。 | 高 | 处理后告警状态变为 resolved；若无其他未处理告警，警报器恢复 standby。 |
| FR-09 | 录像回放 | 系统应保存事件录像记录，并支持按关键词检索。 | 中 | 输入“厨房”能检索到厨房相关录像。 |
| FR-10 | 语音指令 | 系统应解析“打开客厅灯”“启动离家安防”“模拟厨房烟雾”等指令，并支持可选 DeepSeek 解析自然语言指令。 | 高 | 指令执行后返回明确结果并更新对应状态；DeepSeek 不可用时回退到本地规则。 |
| FR-11 | 场景模式 | 系统应支持离家安防、回家模式、夜间巡航、紧急警戒。 | 中 | 启动场景后批量更新设备状态。 |
| FR-12 | 审计日志 | 系统应记录登录后关键操作，包括设备控制、场景切换和告警处理。 | 中 | 管理员可看到最近操作日志。 |

## 6. 非功能需求

| 编号 | 类型 | 需求描述 | 验收方式 |
|---|---|---|---|
| NFR-01 | 性能 | 本地原型常规接口响应时间应控制在 2 秒以内。 | 浏览器操作和接口测试观察。 |
| NFR-02 | 可靠性 | 用户、设备、告警、录像、日志数据应持久化保存。 | 重启服务后数据仍存在。 |
| NFR-03 | 安全性 | 系统应使用登录令牌、密码哈希和接口级权限校验。 | 未登录访问接口被拒绝，访客越权被拒绝。 |
| NFR-04 | 兼容性 | 系统应支持 Windows 环境下的 Chrome / Edge 浏览器。 | 手工兼容性测试记录。 |
| NFR-05 | 可维护性 | 后端应按认证、数据库、业务服务、HTTP 接口分层组织。 | 检查 `src/smart_home/` 代码结构。 |
| NFR-06 | 可测试性 | 核心业务逻辑应可通过自动化单元测试验证。 | `unittest` 测试通过。 |

## 7. 约束需求

- CR-01：项目不得依赖真实硬件，否则课堂演示风险较高。
- CR-02：项目应保证代码源文件不少于 5 个，关键代码行数超过 500 行。
- CR-03：项目应至少实现 3 个核心用例，本系统实际实现 7 个以上核心用例。
- CR-04：系统默认使用本地 SQLite 数据库，降低部署复杂度。
- CR-05：文档、图表和代码应放在统一目录结构下，便于打包提交。

## 8. 核心用例

### UC-01 登录系统

参与者：管理员、家庭成员、访客查看者。

主流程：

1. 用户进入登录页。
2. 输入用户名和密码。
3. 系统校验密码哈希。
4. 校验成功后返回登录令牌和用户信息。
5. 前端进入监控工作台。

异常流程：用户名或密码错误时，系统提示登录失败。

### UC-02 查看实时监控

参与者：管理员、家庭成员、访客查看者。

主流程：

1. 用户登录系统。
2. 系统加载摄像头设备列表。
3. 前端展示多路模拟视频流、房间和摄像头状态。

### UC-03 控制设备

参与者：管理员、家庭成员。

主流程：

1. 用户在设备卡片上点击控制按钮。
2. 前端调用设备状态接口。
3. 后端检查角色权限。
4. 后端更新 SQLite 中的设备状态。
5. 系统记录审计日志并刷新界面。

异常流程：访客执行控制时，系统返回权限错误。

### UC-04 触发并处理异常告警

参与者：家庭成员、管理员、智能设备/传感器。

主流程：

1. 用户或模拟传感器触发入侵、烟雾、跌倒等异常事件。
2. 系统创建告警记录。
3. 系统创建事件录像记录。
4. 系统根据事件类型执行联动策略。
5. 用户确认告警并填写处置说明。
6. 告警状态变更为已处理。
7. 若系统中没有其他未处理告警，声光警报器恢复待命状态。

### UC-05 检索录像回放

参与者：管理员、家庭成员、访客查看者。

主流程：

1. 用户进入录像回放区域。
2. 输入关键词或选择筛选条件。
3. 系统查询录像记录。
4. 前端展示录像标题、时间、房间、事件类型和摘要。

### UC-06 执行语音指令

参与者：管理员、家庭成员。

主流程：

1. 用户输入语音指令文本。
2. 系统检查是否已配置 DeepSeek API 密钥。
3. 若已配置，优先调用 DeepSeek 将自然语言转换为受控动作。
4. 若未配置或 DeepSeek 解析失败，则使用本地关键词规则解析。
5. 若命中场景，则切换场景；若命中告警，则触发模拟告警；若命中设备，则更新设备状态。
6. 系统返回执行结果并写入日志。

### UC-07 管理和审计

参与者：管理员。

主流程：

1. 管理员登录系统。
2. 查看最近设备控制、告警处理、场景切换等日志。
3. 根据日志追溯系统操作过程。
