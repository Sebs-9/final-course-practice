# 项目管理文档

## 1. 文档目的

本文档说明项目计划、团队分工、进度监控、风险管理和版本管理策略。本文档对应课程考核要求中的“2.4 项目管理”和评分标准中的“项目管理 15%”。

## 2. 项目基本信息

| 项目 | 内容 |
|---|---|
| 项目名称 | 全屋智能安防与语音控制系统 |
| 项目周期 | 2 个月 |
| 开发模式 | 迭代式开发，结合敏捷任务拆分 |
| 项目目标 | 完成可运行系统原型和完整软件工程制品 |
| 主要交付物 | 需求文档、设计文档、测试报告、项目管理文档、代码、数据、图表、演示材料 |

## 3. 软件过程模型选择

本项目采用“迭代式 + 轻量敏捷”的过程模型。原因如下：

- 课程周期较短，需要尽快形成可运行原型。
- 全屋智能系统需求较多，适合按核心用例逐步扩展。
- 文档和代码需要保持一致，因此每个阶段都要更新制品。
- 课程考核强调软件工程过程，迭代式开发便于体现需求、设计、实现、测试的闭环。

## 7. 进度监控机制

- 每周至少一次项目进度同步，检查任务完成情况。
- 每个里程碑结束时检查文档、代码和图表是否同步。
- 使用任务编号跟踪需求、设计、实现和测试。
- 缺陷以 BUG 编号记录，修复后更新测试报告。

## 8. 风险管理

| 风险编号 | 风险 | 影响 | 概率 | 应对策略 |
|---|---|---|---|---|
| R01 | 真实硬件接入困难 | 影响演示稳定性 | 高 | 使用模拟设备和传感器数据 |
| R02 | 视频流处理复杂 | 增加开发量 | 中 | 使用 CSS 模拟视频流，重点展示工程流程 |
| R03 | 第三方依赖安装失败 | 影响运行 | 中 | 使用 Python 标准库和原生前端 |
| R04 | 功能过多导致延期 | 影响提交完整性 | 中 | 优先保证登录、看板、告警、录像、语音核心用例 |
| R05 | 文档与代码不一致 | 影响评分 | 中 | 文档按最终代码接口和数据库更新 |
| R06 | 演示时出现权限或数据问题 | 影响课堂展示 | 低 | 提供固定演示账号和种子数据 |

## 9. 版本管理规范

- 主分支保存稳定版本。
- 每个功能以任务编号组织提交说明，如 `T07 implement alert linkage`。
- 文档、图表和代码同时更新。
- 提交前运行自动化测试。
- 重要提交应说明变更内容、影响范围和验证方式。
- 真实提交记录见 `docs/version-history.md`，最终提交包中同步保留该文件，避免用虚假的批量提交记录替代实际开发记录。

## 10. 质量保障

- 代码按模块分层，避免单文件堆叠。
- 关键业务逻辑使用单元测试验证。
- 前端避免依赖外部 CDN，保证离线可运行。
- 数据库自动建表和种子初始化，降低部署风险。
- 提交前按 `deliverables/submission-checklist.md` 检查材料完整性。
