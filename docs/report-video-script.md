## 3. 讲解稿

### 0:00-1:00 开场

大家好，我们小组的软件工程课程实践项目是“全屋智能安防与语音控制系统”，选题方向是全屋智能系统。小组共有 6 名成员，组长是卢鹏宇。项目目标是完成一个可运行的本地 Web 原型，并配套提交需求分析、软件设计、测试计划与用例报告、项目管理文档、UML 图、甘特图、代码和演示材料。

### 1:00-2:30 项目背景

全屋智能系统通常包含摄像头、门窗传感器、烟雾传感器、灯光、空调、门锁和警报器等设备。本项目没有接入真实硬件，而是通过本地模拟数据和 Web 界面展示家庭安防场景。系统重点实现多房间监控、异常告警、录像回放、设备联动、场景模式和语音指令控制，保证课堂演示稳定，同时体现完整的软件工程过程。

### 2:30-4:00 需求分析

系统主要面向管理员、家庭成员和访客三类用户。管理员可以查看日志、控制设备、处理告警和触发模拟事件；家庭成员可以查看状态、控制设备、处理告警和使用语音指令；访客只能查看看板和录像，不能执行控制操作。核心用例包括登录系统、查看监控、控制设备、触发并处理告警、检索录像、执行语音指令和查看审计日志。

### 4:00-6:30 软件设计

系统采用四层架构。表现层由 HTML、CSS 和 JavaScript 实现单页工作台；接口层由 Python HTTP 服务提供 JSON API；业务逻辑层处理认证、设备、告警、录像、语音和场景；数据访问层负责 SQLite 建表、种子数据和查询。数据库中包含用户、房间、设备、告警、录像、场景、场景动作和操作日志等表。这样的拆分让界面、业务逻辑和数据访问相互独立，方便测试和维护。

### 6:30-10:30 系统实操

首先使用管理员账号登录。进入系统后可以看到房间数、设备数、在线设备数、摄像头数和未处理告警数。房屋态势区域展示不同房间的状态，右侧控制区可以直接控制灯光、摄像头、门锁、空调、警报器和传感器。接着在告警中心选择房间和事件类型，例如“厨房烟雾”或“玄关入侵”，系统会创建告警记录、生成录像记录，并根据事件类型联动灯光、摄像头和声光警报器。点击“确认处理”后，告警状态变为已处理；如果没有其他未处理告警，警报器会恢复待命状态。

### 10:30-11:30 语音功能

语音区域支持文本形式的指令模拟。默认情况下，系统使用本地规则解析，例如“打开客厅灯”“查看客厅摄像头”“启动离家安防”“模拟厨房烟雾”。如果保存了 DeepSeek API 密钥，系统会优先调用 DeepSeek 将自然语言转换为受控动作；如果 DeepSeek 未配置或解析失败，会回退到本地规则，保证演示稳定。

### 11:30-12:30 权限与安全

系统使用密码哈希和登录令牌进行认证，并在接口层和业务层校验角色权限。管理员和家庭成员可以控制设备、处理告警和使用语音指令，访客只能查看看板和录像。演示时可以切换到访客账号，尝试控制设备，系统会拒绝该操作，从而体现权限控制。

### 12:30-13:30 测试结果

项目使用 Python `unittest` 进行自动化测试，命令是 `python -m unittest discover -s tests -v`。当前共有 31 个测试全部通过，覆盖登录、权限、设备控制、告警联动、自动化规则、录像检索、场景模式、语音指令、DeepSeek 配置、DeepSeek 回退、接口安全和性能检查。测试报告中也记录了已修复缺陷，例如摄像头查询误判和告警处理后警报器未恢复的问题。

### 13:30-14:30 项目管理

项目按 2 个月周期规划，采用迭代式和轻量敏捷方式推进。前期完成选题收敛和需求分析，中期完成架构、数据库、接口和前端工作台，后期完成测试、缺陷修复、演示材料和最终提交检查。组长卢鹏宇负责项目协调和材料统筹，其他成员分别负责需求、后端、前端、测试和部署演示材料。

### 14:30-15:00 总结

本项目完成了一个可运行的全屋智能安防原型，也完成了需求、设计、测试、项目管理、图表、代码和提交清单等软件工程制品。后续如果继续扩展，可以接入真实摄像头、真实 IoT 网关、浏览器语音识别、移动端推送和更完整的用户管理。
