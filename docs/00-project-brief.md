# 项目立项说明

## 1. 项目定位

项目名称：全屋智能安防与语音控制系统

选题来源：《软件工程实践选题说明》中的“选题方向一：全屋智能系统”。

项目目标：构建一个可运行的本地 Web 原型系统，用于展示全屋智能环境中的设备接入、远程监控、异常识别、报警处理、录像回放、语音指令和场景联动能力，并配套完成需求分析、软件设计、系统测试和项目管理文档。

## 2. 选题收敛

选题文档在全屋智能方向下给出两个子题：

- 智能家居语音交互助手系统设计与实现。
- 家居视频监控与安防智能系统设计。

本项目建议以第二个子题“家居视频监控与安防智能系统”为主，因为课程考核 PDF 中的示例也以家用智能视频监控系统展开，需求、设计、测试和评分点都更容易对齐。为体现“全屋智能”完整性，原型中加入语音指令和场景模式，覆盖第一个子题的核心交互特征。

## 3. 需求范围

### 3.1 范围内功能

- 用户登录与角色权限：管理员、家庭成员、访客查看者。
- 全屋设备管理：摄像头、门窗传感器、烟雾传感器、灯光、空调等设备的状态查看与控制。
- 实时监控看板：多房间摄像头模拟画面、设备在线状态、当前告警、环境状态。
- 智能异常检测：基于模拟事件规则识别入侵、门窗异常、烟雾、老人跌倒等风险。
- 联动应急响应：异常发生后自动生成告警，联动灯光、通知、模拟拨打电话、记录处置日志。
- 录像与事件回放：按时间、房间、事件类型筛选历史记录，展示模拟录像片段和事件时间线。
- 语音指令控制：提供文本形式的语音指令模拟入口，解析“打开客厅灯”“查看门口摄像头”“启动离家模式”等指令。
- 场景模式：离家安防、回家模式、夜间巡航、紧急警戒等自动化规则。
- 系统设置与审计：用户、房间、设备、规则、操作日志的管理。

### 3.2 范围外功能

- 不接入真实摄像头、真实云台或真实智能家居硬件。
- 不训练真实计算机视觉模型，异常检测采用可解释的规则与模拟数据。
- 不实现真实短信、电话或移动端推送，只做系统内模拟。
- 不部署到公网云服务器，默认本地运行。

这样处理能让项目在课程时间内稳定交付，同时仍能体现完整的软件工程过程和智能系统业务逻辑。

## 4. 核心用例

- UC01：用户登录系统并进入对应权限的工作台。
- UC02：用户查看多房间实时监控和设备状态。
- UC03：系统检测异常事件并触发联动报警。
- UC04：用户确认、处理、关闭报警并查看处置记录。
- UC05：用户按条件检索录像和历史事件。
- UC06：用户通过语音指令控制设备或切换场景模式。
- UC07：管理员维护设备、房间、自动化规则和用户权限。

实现用例数量不少于 3 个，满足考核 PDF 中“实现用例不足 3 个可能被认定规模过小”的约束。

## 5. 非功能目标

- 性能：本地原型常规操作响应时间控制在 2 秒以内。
- 可靠性：使用 SQLite 持久化用户、设备、告警、录像和日志数据，重启后数据不丢失。
- 安全性：登录认证、角色权限、密码哈希、接口权限校验、操作审计。
- 兼容性：优先支持 Windows 本机 Chrome / Edge 浏览器。
- 可维护性：后端按路由、服务、数据访问、模型、种子数据分层组织；前端按页面、组件、样式、API 访问分离。
- 可测试性：为登录、设备控制、告警生成、录像筛选、语音指令解析等关键流程准备测试用例。

## 6. 技术路线

默认技术路线：

- 后端：Python 标准库 HTTP 服务。
- 数据库：SQLite。
- 前端：原生 HTML、CSS、JavaScript。
- 图表与监控画面：原生 Canvas / CSS 实现，避免外部依赖。
- 测试：Python `unittest`，配合接口级和服务级测试。

采用该路线的原因是依赖少、便于本地运行、提交包可控，不会因为安装第三方库失败影响最终演示。若你希望改为 Flask/FastAPI/Vue 等技术栈，可以在本阶段审阅时调整。
