# 工作拆分与审阅节点

## 原则

该项目按阶段推进。每个阶段完成后先停下，提交当前产物和风险说明，由你审阅后再进入下一阶段。

## 阶段 1：立项与范围确认

状态：已开始。

交付物：

- `README.md`
- `docs/00-project-brief.md`
- `docs/01-work-breakdown-and-review-gates.md`
- `docs/02-scoring-map.md`

审阅重点：

- 是否接受“安防监控为主、语音控制为辅”的题目收敛。
- 是否接受使用模拟视频流、模拟传感器和规则检测。
- 是否接受轻量本地 Web 技术路线。

## 阶段 2：需求分析制品

目标：完成可用于评分的需求分析文档初稿。

交付物：

- `docs/requirements.md`
- 用例图原始素材。
- 需求优先级表。
- 功能需求、非功能需求、约束需求和验收标准。

审阅重点：

- 需求是否覆盖全屋智能系统业务场景。
- 用例是否足够清晰、可验证。
- 是否存在你们小组不想实现或不想展示的功能。

## 阶段 3：软件设计制品

目标：完成架构、数据库、接口和界面设计。

交付物：

- `docs/design.md`
- 架构图、ER 图、顺序图、活动图、状态图原始素材。
- API 设计表。
- UI 页面结构和交互说明。

审阅重点：

- 架构是否和后续代码实现一致。
- 数据库表是否能支撑需求和测试。
- 页面是否适合课堂演示。

## 阶段 4：原型开发 Sprint 1

目标：实现可启动的系统骨架和核心业务闭环。

计划功能：

- 登录与角色权限。
- 设备和房间数据初始化。
- 实时监控看板。
- 设备状态控制。
- 基础操作日志。

审阅重点：

- 系统能否顺利启动和访问。
- 主界面是否符合预期。
- 代码结构是否适合继续扩展。

## 阶段 5：原型开发 Sprint 2

目标：实现智能安防和全屋联动能力。

计划功能：

- 异常事件模拟与检测。
- 告警列表、告警处置、联动策略。
- 录像与事件回放。
- 语音指令解析。
- 场景模式切换。

审阅重点：

- 演示流程是否足够完整。
- 智能化表现是否明显。
- 是否需要加入更强的视觉展示或额外页面。

## 阶段 6：测试、文档完善与提交材料

目标：补齐评分材料并形成最终提交包。

交付物：

- `docs/test-plan-and-cases.md`
- `docs/project-management.md`
- `docs/deployment-and-user-guide.md`
- 测试代码与测试结果。
- 项目截图素材。
- 演示 PPT 大纲和汇报视频脚本。
- 最终打包说明。

审阅重点：

- 材料是否覆盖评分点。
- 测试用例是否能支撑“系统无明显 Bug”的结论。
- 演示顺序是否适合 5 分钟课堂展示。
