# 组员分工与课程实践心得模板

## 1. 组员角色分工说明

| 成员 | 角色 | 主要工作 | 工作情况说明 |
|---|---|---|---|
| 成员 A | 项目经理/组长 | 计划制定、任务协调、文档整合、汇报组织 | 按阶段推进项目，负责提交材料完整性检查。 |
| 成员 B | 需求分析 | 需求分析、用例建模、需求文档 | 完成利益相关方、功能需求和非功能需求分析。 |
| 成员 C | 架构与后端开发 | 架构设计、数据库、接口、业务逻辑、测试 | 完成系统核心原型和自动化测试。 |
| 成员 D | 前端与演示 | 页面设计、交互实现、截图和演示材料 | 完成工作台界面和演示流程准备。 |

## 2. 课程实践心得模板

每位成员控制在 400 字以内。

### 成员 A 心得

本次课程实践让我对软件工程中的需求、设计、实现、测试和项目管理有了更完整的认识。项目并不只是写代码，还需要在开始阶段明确边界和目标，并在实现过程中持续检查文档与系统是否一致。作为项目经理，我重点关注任务拆分、进度控制和材料完整性，也认识到风险管理对课程项目同样重要。通过全屋智能安防系统的实践，我理解了用例、架构图、ER 图、测试用例等制品如何共同支撑一个可运行的软件系统。

### 成员 B 心得

本次实践中，我主要负责需求分析和用例建模。通过分析家庭成员、管理员、访客和智能设备等利益相关方，我认识到需求描述必须清晰、完整且可验证。全屋智能系统看似功能很多，如果不进行范围收敛，很容易导致实现困难。因此我们将重点放在安防监控、告警联动、录像回放和语音控制上，并为每个需求设置验收标准。这让我理解到需求分析是后续设计、编码和测试的基础。

### 成员 C 心得

我主要负责架构设计、后端实现和测试。实践过程中，我体会到分层设计和模块化对代码维护非常重要。系统将认证、数据库、业务服务和 HTTP 接口拆分到不同文件，使设备控制、告警联动、语音指令和场景模式能够独立开发和测试。通过编写单元测试，我也更直观地理解了测试对保障系统正确性的作用。相比只完成界面，软件工程更强调可运行、可验证和可维护。

### 成员 D 心得

我主要负责前端界面和演示流程。通过设计监控看板、设备卡片、告警列表、录像检索和语音输入区域，我认识到界面设计需要围绕用户任务展开，而不是只追求视觉效果。全屋智能系统的用户需要快速判断家庭安全状态，因此页面要突出告警、摄像头和设备状态。在准备演示材料时，我也体会到清晰的演示流程能够更好地展示项目价值和软件工程过程。
