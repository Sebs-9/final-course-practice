## 2. 课程实践心得

每位成员控制在 400 字以内。

### 丁天心得

本次课程实践让我对软件工程中的需求、设计、实现、测试和项目管理有了更完整的认识。项目并不只是写代码，还需要在开始阶段明确边界和目标，并在实现过程中持续检查文档与系统是否一致。我重点关注任务拆分、进度控制、代码整合和材料完整性，也认识到风险管理对课程项目同样重要。通过全屋智能安防系统的实践，我理解了用例、架构图、ER 图、测试用例等制品如何共同支撑一个可运行的软件系统。

### 张星宇心得

本次实践中，我主要参与系统前端交互和可视化演示实现。全屋智能系统需要让用户快速理解各房间设备状态，因此界面不仅要能操作，还要能直观看到场景变化。在完善客厅演示、设备状态反馈和页面滚动体验时，我认识到前端开发需要围绕实际使用流程组织信息，而不是只做静态页面。通过持续修正界面问题，我也理解了实现、测试和演示之间需要反复对齐。

### 王胜航心得

本次课程实践中，我主要参与测试验证和课堂汇报准备。通过检查登录、设备联动、场景切换、告警记录和页面展示等功能，我认识到测试不是简单确认页面能打开，而是要从用户操作路径出发，判断功能是否符合需求。准备汇报时，我也认识到需要把需求、设计、实现和测试串联讲清楚，才能让别人快速理解系统价值。

### 包可豪心得

本次实践中，我主要参与需求整理、用例分析和前端风格调整。全屋智能系统功能范围较广，如果没有明确需求边界，后续实现和测试都会变得混乱。通过梳理家庭成员、访客、设备和系统管理员等对象，我认识到需求描述需要清楚说明输入、处理过程和验收标准。参与前端风格修改和 GitHub 提交后，我也理解到实现、协作和最终展示之间需要保持一致。

### 卢鹏宇心得

通过本次课程实践，我认识到软件工程课程项目不仅关注代码实现，也关注提交材料的完整性。参与选题信息、成员信息和提交要求整理时，我了解到需求文档、设计文档、测试报告、项目管理文档和演示材料各自承担不同作用。辅助核对材料的过程让我认识到，最终交付需要清晰的目录结构和完整的支撑材料。以后参与类似项目时，我会更早参与具体任务。

### 李智星心得

本次课程实践让我了解到软件项目最终提交并不是简单上传代码，还需要清晰的操作步骤和演示材料。浏览系统网站并提出反馈时，我认识到页面布局、导航固定和按钮状态会直接影响别人理解项目。通过参与演示检查，我对软件工程中的需求、设计、实现、测试和交付环节有了基本认识。之后我会更多参与实际开发和验证任务。
